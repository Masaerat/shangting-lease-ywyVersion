# 分层上下文记忆与 RAG 评测升级规格

日期：2026-09-06；目标分支：`agentRag`。

## 边界

仅修改后端、测试和后端文档。保留 Spring AI 1.0.0，不引入 MCP，不修改前端，不把外部模型或真实向量库未执行的结果写成已验证结论。保留当前工作区中已经存在的 Docker、模型配置、MQ 和文档改动。

## 已确认现状

1. 对话历史按 `userId + conversationId` 存在 Redis，默认保存最近 10 轮并直接删除最早消息，TTL 为 2 小时；早期预算、区域和排除条件可能丢失。
2. 历史是字符串列表，没有结构化业务状态、摘要版本和压缩状态；同会话并发写存在进程内覆盖风险。
3. RAG 已有标题感知切片、查询改写、向量召回、本地知识兜底、启发式重排和引用，但当前运行环境 `vector_store` 为 0 条。
4. 现有 10 条评测只覆盖本地关键词分类并得到 HitRate@1/MRR=1.0，不能证明 Embedding、PGVector、回答忠实度或无答案拒答能力。
5. 当前只要向量调用未抛异常就标记 `HYBRID`，即使向量返回 0 条；不同来源的原始分数直接相加也不利于稳定对比。

## 目标一：分层上下文记忆

采用“结构化状态 + 滚动摘要 + 最近原文”的分层记忆，不额外调用大模型：

- 最近原文：保留最近若干完整用户/助手消息，处理指代、追问和刚发生的工具结果。
- 结构化状态：确定性提取城市、区域、最低/最高预算、租住方式、房源编号、联系电话和偏好；用户最新明确表达覆盖旧值。
- 滚动摘要：超过轮数或字符预算时，把最早完整轮次压缩为带角色的摘要片段；摘要有长度上限，同时保留开头与最新部分。
- 上下文组装顺序：已确认条件、历史摘要、最近原文、当前问题。结构化状态只是用户偏好，不能替代数据库/工具事实。
- 新格式使用带 `schemaVersion`、`revision` 的 JSON 信封，并兼容读取旧 JSON 字符串数组和换行格式。
- 同一 JVM 内按会话做条带锁，避免同时请求发生读改写覆盖；Redis 故障仍降级为空历史，不能让已完成工具调用重复执行。
- 历史继续沿用现有用户隔离和 TTL；本轮不实现跨设备永久长期记忆和跨实例 Redis CAS。

## 目标二：可复现的 RAG 评测闭环

- 建立版本化 JSONL 黄金数据集，覆盖押金、付款、预约、报修、退租、入住材料、同义改写和无答案问题。
- 分开评估检索和回答；本轮先实现不依赖外部模型的检索指标：HitRate@K、MRR、无答案正确率、同义问题 Top-K 一致性及模式分布。
- 报告必须展示数据集版本、样本数、检索模式分布和指标，明确 `LOCAL` 结果不是向量评测。
- 混合召回使用 RRF 合并向量排名与本地词法排名，避免直接混合不可比较的原始分数；分类匹配只作为小幅、可配置的确定性加成。
- 排序在相同分数下按稳定键排序，保证相同输入可复现。
- 检索模式按真实命中标记为 `HYBRID`、`VECTOR`、`LOCAL` 或 `EMPTY`；向量异常记录降级日志。
- 增补入住材料本地知识及口语同义词，证据不足继续返回空结果，不补造无关知识。
- 保留现有 `topK=5`、阈值 `0.75` 作为未调优基线；只有真实语料导入并运行外部评测后才允许声明向量准确率提升。

## 验收标准

1. 早期预算和城市在原始消息被压缩后仍出现在结构化上下文；用户后续修改预算能覆盖旧值。
2. 多行消息、旧缓存格式、用户隔离、Redis 读写失败和字符预算压缩均有测试。
3. RRF 合并、稳定排序、向量空结果模式、向量失败降级和无答案结果均有测试。
4. 数据集由资源文件加载，不再在测试代码中硬编码；测试报告不能把本地兜底冒充真实向量效果。
5. 执行限定后端单元测试及编译；外部 Embedding/PGVector 评测若未运行必须显式记录。
